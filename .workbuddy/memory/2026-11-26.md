## v1.43.0 播放页「画面」按钮合并

- 用户反馈：播放页「画面比例」和「画面大小」看着像同一个功能，要求合并成一个按钮。
- 事实确认：两者确实是两步——比例决定内容形状（`shaped` 用 `BoxFit.fill` 填进目标形状），大小决定形状怎么塞进 `_stageAreaSize`。`_stageAreaSize` 只在 cover/fill 时占满高度，所以「自适应 + 适配屏幕」时两者观感一致，用户误判很正常。
- 改法（`lib/pages/play_page.dart`）：
  - `_aspectPanelOpen` + `_scalePanelOpen` → 单个 `_screenPanelOpen`；`_buildAspectPanel` + `_buildScalePanel` → `_buildScreenPanel()`（Column 内两段 `_buildPanel`，第一段 `bottom: 6` 收窄间距）。
  - `_buildPanel` 新增 `double bottom = 10` 参数。
  - 按钮只剩一个：icon `aspect_ratio_rounded`，label 固定「画面」，`active` = 面板开 || 比例非自适应 || 交换宽高 || 填充方式非默认（同倍速按钮常亮逻辑）。
  - 底部按钮行竖屏多集时从 8 个降到 7 个。
- 静态校验：0 error / 0 warning / 31 info（基线）。**未跑 `dart format`**。
- 版本 1.43.0+242（pubspec + local.properties），`更新记录.MD` 已加条目。
- 提交 `562b6078`，仅本地，**未 push**。
- 遗留风险：合并面板比原「比例」面板高约 40px，超小窗口（桌面 < 300 高）理论上仍可能 RenderFlex 溢出，属旧有问题量级，未处理。

## v1.44.0 多播放线路

- 用户报「有些站聚合了好几个站点的播放链接，App 详情页看不到」。实测 `https://ys.cxkjg.cn/api/provide/vod`（`ac=detail&ids=164368`，`ac=videolist&ids=` 同样）：
  `vod_play_from` = 金鹰$$$闪电$$$非凡$$$量子$$$WS$$$速博$$$HD(SN)$$$红牛$$$U酷$$$光速$$$樱花，11 条；`vod_play_url` 11 段，集数 19/16/19/21/19/19/19/19/19/15/17。
- 根因：`http_service._mapPlayList` 用 `firstWhere(含 m3u8)` 只取一段，`vod_play_from` 从未读；xml 侧 `<dd flag>` 遇到第一个也 break。
- 改法：
  - `PlayLine(name, items)`；`VideoDetail.lines` 为唯一真源，`m3u8List` 变 getter 取 `lines.first.items`（旧的 fromJson/toJson 存档仍兼容）。
  - `_mapPlayLines()` 逐段配对两个 `$$$` 数组，名字缺失补「线路N」，**含 m3u8 的线路排前**（保留旧「优先 m3u8」语义）；xml 侧遍历全部 `<dd>`，flag 当线路名。
  - 详情页：`_lines/_lineIndex`，播放按钮上方横滑线路条（名称+集数），`_selectLine` 只换 `_playList`；`PlayPage(initialLine:)`。
  - 播放页：`_lines/_lineIndex`，右栏 + 选集弹窗（`StatefulBuilder` 局部维护 lineIdx/list）都能切；`_switchLine` 按集名对齐、对不上按原位置就近；`_loadDetail` 里用 `widget.url` 反查所属线路（历史/收藏进来不会串台）；单集多线路时也显示「选集」按钮。
- 静态校验 0 error / 0 warning / 31 info。版本 1.44.0+243。提交 `bb11dc11`，**未 push**。
