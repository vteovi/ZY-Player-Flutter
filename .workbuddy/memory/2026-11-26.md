## v1.44.1 清除死站的进度提示

- 用户反馈：源管理页点「清除死站」→ 确认删除后「页面啥也不动」，怀疑假死。
- 根因有两层：
  1. `_clearDead` 删完才 `showToast`，中间界面零反馈（`_batchRunning` 只覆盖检测）；
  2. 更硬的一层是 `ZyDatabase.removeMany` 里 `for (...) await store.remove(...)`——
     `SharedPreferences` 没有批量删除接口，每次 `remove` 都是「整份偏好重新
     json.encode + writeAsStringSync」，**同步阻塞 UI 线程**（与 `importRaw`
     里记录的 Windows 端行为一致），删几十条 = 几十次全量重写，界面自然僵住。
- 改法：
  - `removeMany(db, targets, {onProgress, isCancelled})`：先落 key 列表（中断也不会
    留下指向已删条目的 key），再逐条删；30 条以内每条 `Future.delayed(Duration.zero)`
    让出一次事件循环，更多时按 12 条 / 24ms 预算让出；小批量每条报进度，>40 条每 5 条报。
  - `AppState.removeSites` 透传 `onProgress`。
  - `site_page`：`_clearing/_clearDone/_clearTotal` + `_removeWithProgress()`，
    按钮显示「清除中 3/12」，工具栏下 2px `LinearProgressIndicator`，`idle` 纳入
    `_clearing` 一并禁用其余按钮；「清空所有源」「清理重复页」共用。

## v1.45.0 详情页左右滑动切换线路

- 用户需求：详情页加左右滑动切线路，且切换后线路名必须可见、选中项要跟着滚。
- 实现（`detail_page.dart`）：
  - 内容区外包 `GestureDetector(onHorizontalDrag*)`，累加 `_lineDragDx`，抬起时阈值 **48px 位移或 320px/s 速度**，斜滑/纵向滚动时的横向抖动不会误切；向左滑 = 下一条。到头 `HapticFeedback.selectionClick()` 提示不再切。
  - 每个线路 chip 的 `Container` 挂 `GlobalKey`（`_lineKeys`，在 `_load` 的 setState 里随 `_lines` 重建）。切换后 postFrame 调 `Scrollable.ensureVisible(alignment: 0.5, 260ms easeOutCubic)`——它会顺着**所有祖先 Scrollable** 对齐，所以横向把 chip 滚到中间、纵向在页面滚到底时把线路条拉回视口，一举两得。
  - 标题行改 Row：`Expanded(播放线路 · xx（N 集）)` + `Icons.swipe` + 「左右滑动切换」，仅多线路显示。
  - `_lines.length < 2` 不挂 GestureDetector，避免和纵向滚动/SelectionArea 抢手势。
- 注意：线路条自身的横向 SingleChildScrollView 在竞技场里更深，会优先吃掉滑动 → 在标签上滑只滚标签不切线路，这是有意的（否则后面的线路选不到）。
- 静态校验 0 error / 0 warning / 31 info。版本 **1.45.0+246**（pubspec + local.properties）。提交 `d1396600`（dev），未 push、未构建。
