## 设备同步「连接超时」排障（未改代码）
- 现象：手机 A 开启共享（1.14.2），手机 B 连接同步（1.14.1）报
  `SocketException: HTTP connection timed out after 0:00:08, host 192.168.31.72:9527`。
- 结论：与版本无关。超时发生在 TCP 握手阶段，HTTP 一个字节都没交换，不存在协议/版本协商；
  1.14.1 与 1.14.2 的同步代码完全相同（sync_service 最后改动在 1.12.1，sync_page 在 1.12.0）。
  版本不匹配的典型表现是「连接被拒绝 / HTTP 404 / 响应格式错误」，都是秒回而非 8 秒超时。
- 根因：Wi-Fi 侧网络状态问题。用户把 B **断开 Wi-Fi 重新连接**后即恢复正常。
  可用"组播能过、单播 TCP 不通"解释——路由器的组播转发与单播转发表是两条路径，
  跨 AP/跨频段（Mesh 多节点、2.4G/5G 分 SSID）时常见只拦客户端间单播。
  次要可能：DHCP 租约/ARP 表过期、共享端锁屏或退后台、连接端开着 VPN 类 App。
- 排障口诀：先让两端各自断开重连 Wi-Fi；再确认同一 SSID；共享端保持亮屏在前台；
  连接端关 VPN；浏览器开 `http://<ip>:9527/sync` 见 JSON 即链路通。
- 遗留可做（未做，用户暂不需要）：失败原因中文化（超时/拒绝/不可达分别给建议）、
  连接同步栏加「测试连接」按钮（3 秒只探测不写数据）、设备列表 8 秒收不到广播自动剔除
  （当前只增不减，停止共享后仍残留，容易被误认为对方在线）。

## 新增三 ABI 打包脚本 tools/build_apk_all_abi.bat（提交 fd9929c）
- 用户问能否出 ARMv8 / ARMv7 / x86_64 三个 APK：可以，`flutter build apk --release --split-per-abi`
  一次出三个。**不传 `--target-platform` 时默认架构就是 android-arm + android-arm64 + android-x64**
  （见 flutter_tools `commands/build_apk.dart` 的 `_kDefaultAotArchs`）；输出名为
  `app-<archName>-release.apk`，archName 分别是 arm64-v8a / armeabi-v7a / x86_64。
- 现有 `build_apk.bat`（不带 split，实际出 fat 包）与 `build_apk_arm64.bat`（带 split 只出 arm64）保持不动，
  新脚本独立：一次构建、拷三个包到根目录、打印体积 + SHA1，缺 ABI 走 PARTIAL 分支。
- 工程侧无阻碍：`android/app/build.gradle.kts` 与 video_player_android 都**没有 abiFilters**，
  依赖里也没有带 jniLibs 的第三方插件（media3/sqflite/file_picker 都是纯 Java/Kotlin），三 ABI 都能出。
- 纯构建脚本，不进 APK，**不升版本号**。
- 生成方式：`.bat` 不能用 Write 工具（会存成 UTF-16），用 Python `open(..., encoding='gbk', newline='\r\n')` 写；
  CRLF 必须保留（`od -c` 验证 `\r \n`）。
- 验证方式：把脚本里的 flutter build / dart 探针 / reg 提权 / pause / taskkill 替换成空操作、
  SRCDIR 指向假 APK 目录做干跑，确认版本解析 `1.15.0`、清理循环、`:copy_one` 子过程、
  MISSING/PARTIAL 与 BUILD OK + SHA1 汇总全部正常。注意本环境 **reg.exe 与 cmd.exe 在沙箱黑名单**里，
  干跑必须摘掉 reg 提权行、并用 PowerShell 直接执行 .bat（不能从 Bash 调 cmd）。
