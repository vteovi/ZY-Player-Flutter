## 修复「搜索结果卡片没有封面」（commit e9c1f70d，1.21.1+204，dev）
- 现象（用户原话）：「有些搜索结果卡片，图片不显示，点进去后图片又能显示，返回搜索结果又还是一样」。
- **根因**：`HttpService.search` 只传了 `wd`，走采集站默认的 `ac=list`；maccms 的 `ac=list` 只回精简字段（vod_id / vod_name / vod_remarks…），**不含 vod_pic**。而 `fetchList`（首页）与 `fetchDetail`（详情页）都带 `ac=videolist`，所以首页、详情都有图，唯独搜索结果没有。`_apiUrl` 用 `Uri.replace(queryParameters: {...自带, ...新参数})`，同名覆盖，所以站点自带的 `?ac=list` 会被正确替换。
- **实测证据**（Python + `ProxyHandler({})` 绕代理）：红牛/极速/新浪/火狐 4 个源，`?wd=流浪地球` 返回的 5 条 `vod_pic` **全是空串**；换成 `?ac=videolist&wd=` 或 `?ac=detail&wd=` 后 **3/3 全有图**（如 `https://hongniuzyimage.com/cover/xxx.jpg`）。
- 修法：`search` 改带 `{'ac': 'videolist', 'wd': kw}`；若返回的不是结构化数据（`json == null && xmlDoc == null`，即网页/空正文）或请求抛异常，**退回老参数再试一次** —— 宁可没封面也不能搜不到（成功但 list 为空的不回退，那是真没结果，避免每次关键词无结果都多打一倍请求）。
- 顺带 `_videosFrom(payload)` → `_videosFrom(payload, site)` + 新增 `_absolutePic`：补全三种不规范封面地址（`//host/a.jpg` → `https:`、`/upload/a.jpg` → 拼接口 origin、`img.host.com/a.jpg` → 补 `http://`，首段像图片文件名时不补，避免 `upload/a.jpg` 被误拼）。4 个调用点全部传 site。
- 版本 fix → PATCH：1.21.0+203 → **1.21.1+204**（pubspec + android/local.properties 同步）；更新记录.MD 加 v1.21.1。
- CI `Analyze` on e9c1f70d → success。**未发版**（等用户构建验收）。

## 横版卡片比例 16:9 → 16:10（commit 9cff8526 + b77ed2c9，1.21.2+205，dev）
- 关键认知：**网格的 `childAspectRatio` 是「整张卡片」的宽高比，封面只是其中一部分**（卡片 = 封面 + 上下 margin 12 + 两行文字 56）。以前横版死写 `1.38`，只是碰巧在手机 1 列（卡宽 366）时接近 16:9；平板 2 列（卡宽 282）实测被拉到 **1.90**，明显偏扁。所以「改个固定数字」在不同屏宽下必然不准。
- 修法：按卡宽算。`ratio = 格宽 / (封面高 + 卡片上下 margin 12 + 文字区 56)`，其中 `封面高 = (格宽 - 12) / (16/10)`。脚本验证 320~2000 屏宽（1~5 列）封面比全部 **1.6000**。
- 结构：`videoGridDelegate(context)` 拆成 `landscapeGridDelegate(availableWidth)` / `portraitGridDelegate(width)` 两个纯函数（返回类型写 `SliverGridDelegateWithMaxCrossAxisExtent`，这样调用处还能读 `maxCrossAxisExtent` 算 `memCacheWidth`）；三个使用点（VideoGridView、VideoGridSkeleton、star_page `_buildPane`）统一改成 `LayoutBuilder` + **真实可用宽度**（`constraints.maxWidth - 12`）。
- ⚠️ **坑：LayoutBuilder 的 builder 在 layout 阶段执行，不能在里面读 InheritedWidget**（会触发「依赖注册发生在 layout」断言）。所以 `context.select<AppState,...>` 与 `MediaQuery.of` 都提到 `build` 阶段算好，再闭包传进去。收藏页 `_buildPane` 同理。
- 顺带修掉竖版列数的老毛病：以前用 `MediaQuery.size.width` 判断档位，大屏带 NavigationRail 时算多一列（每列偏窄），现在用实际可用宽，更准。
- 覆盖范围：首页分类、搜索结果、收藏/历史、骨架屏（骨架屏形状必须跟着变，否则加载完会跳版）。
- 旧的 `videoGridDelegate(context)` 便捷版已删（无调用点），注释里的 dartdoc 引用一并改掉。
- CI `Analyze` on 9cff8526 / b77ed2c9 均 success。**未发版**，等用户验收。
