## 新增 GitHub Actions 云端构建 APK（未 push，本地提交 4383aae2）

用户问「如何在 GitHub 上构建这个 APK」，落地为 CI 配置，不是只给方案。

### 关键事实（之前没记，很重要）
- **`android/app/build.gradle.kts` 的 release 用的是 debug 签名**（`signingConfig = signingConfigs.getByName("debug")`），项目里没有自有 keystore，`.gitignore` 也忽略了 `*.jks` / `android/key.properties`。
- 因此本地 release 包的签名来自 `~/.android/debug.keystore`（首次构建自动生成，密码 `android`、别名 `androiddebugkey`）。
- **runner 每次构建都会随机生成一个新的 debug keystore** → 云端包与本地包签名不同 → 手机上装过本地版本就**无法覆盖安装，必须先卸载**。这是 CI 出包最容易踩的坑。
- 解决办法（已做进 workflow，可选）：把本地 `debug.keystore` base64 存 Secret `DEBUG_KEYSTORE_BASE64`，构建前还原到 `$HOME/.android/debug.keystore`，云端包签名即与本地一致；另可配 `DEBUG_KEYSTORE_PASSWORD`（默认 `android`）。未配置时打印 `::notice::` 继续构建。

### 文件
- `.github/workflows/build-apk.yml`：`workflow_dispatch`（input `variant` = split / fat / both）+ `push: tags: v*`。
  - JDK 17（temurin）+ `subosito/flutter-action@v2`（`3.32.6`，`cache: true`）+ `actions/cache@v4` 缓存 `~/.gradle/{caches,wrapper}`
  - 构建前用 `sdkmanager` 补齐 **NDK 27.0.12077973**（`build.gradle.kts` 硬编码，runner 上不一定预装）；compileSdk 平台交给 AGP 自动下载
  - split → `flutter build apk --release --split-per-abi`；fat → `flutter build apk --release`
  - 上传 `actions/upload-artifact@v4`（保留 30 天）；tag 推送时用 `gh release create/upload` 发 Release（`permissions: contents: write`）
  - `timeout-minutes: 60`，首次含 NDK/依赖下载预计 20~30 分钟
- `tools/ci-collect-apk.sh`：按 ABI 把产物重命名为 `ZY-Player-v<版本>-<arm64|armv7|x86_64|universal>.apk`，**幂等**（`[ -f ] && continue`）。之所以抽成脚本并在两次构建后各调一次：`both` 模式下第二次 `flutter build` 可能覆盖 `build/app/outputs/flutter-apk/`，放最后统一收集会丢第一批。
- `.gitattributes` 追加 `*.sh text eol=lf`：本机 `core.autocrlf=true`，CRLF 的 .sh 在 Linux runner 上会报 `$'\r': command not found`。已确认仓库内 `.sh` 与 `.yml` 均为纯 LF。
- README 补「在 GitHub 上构建（GitHub Actions）」一节。
- **CI 配置不进 APK，按惯例不升版本号**（与 `tools/*.bat` 一致），仍 `1.17.0+191`。

### 验证方式（无构建权限，做的是静态/干跑验证）
- PyYAML 解析 workflow 通过（14 个步骤，触发/权限/steps 结构正确）。
- 用本地已有真实产物跑 `tools/ci-collect-apk.sh 1.17.0`：4 个包正确分类（arm64 33M / armv7 27M / universal 69M / x86_64 35M），第二次调用 0 新增（幂等）。

## 版本更新功能改为真实实现（提交 f2eeb35，1.18.0+192）

用户说「软件内部有一个版本更新功能，修改为正确的方式」—— 查证后确认原来是**假的**：
`me_page.dart` 里 `_MenuItem(title: '版本更新', subtitle: '1.17.0', onTap: () => showToast(context, '当前已是最新版本'))`，
subtitle 写死、点击永远提示已是最新。

### 实现（分层）
- `lib/utils/version.dart`（新）：`UpdateException` / `UpdateInfo`（清单模型 + 宽松字段解析）/
  `VersionRules.isNewer` + `compareNames`。**不 import 任何 Flutter 包**，所以能用纯 `dart run` 验证。
- `lib/services/update_service.dart`（新）：`fetchManifest`（12s 超时；404 / 非 JSON / 超时 / 断网都翻成人话）、
  `download`（流式 + 进度 + 可取消 + 前两字节 `PK` 校验挡掉「下载到网页」）。`export '../utils/version.dart'`，
  调用方只 import 这一个。
- `system_control.dart`：新增 `appVersionName/appVersionCode/canInstallPackages/openInstallPermissionSettings/installApk/openUrl`。
- `MainActivity.kt`：对应 6 个通道方法；`installApk` 用 `FileProvider.getUriForFile(this, "${packageName}.fileprovider", file)`
  + `ACTION_VIEW` + `application/vnd.android.package-archive`。
- `AndroidManifest.xml`：`REQUEST_INSTALL_PACKAGES` + `<provider androidx.core.content.FileProvider
  authorities="${applicationId}.fileprovider">`；`res/xml/file_paths.xml` 放行 cache 根（Dart `getTemporaryDirectory()` = cacheDir）。
- `android/app/build.gradle.kts`：显式 `implementation("androidx.core:core:1.13.1")`（本机 gradle 缓存里已有该版本，离线可编）。
- `me_page.dart`：`_checkUpdate` 全流程 + `_VersionUpdateTile`（副标题读系统版本）+ `_CheckingDialog` /
  `_DownloadDialog` / `_UpdateUrlDialog` 三个组件。
- `AppConfig.updateUrl` + `AppState.setUpdateUrl`：清单地址可改（默认 GitHub raw），失败弹窗里有「设置更新地址」，
  哨兵值 `_UpdateUrlDialog.useDefault` 表示恢复默认。
- `update.json`（新，仓库根）：当前写 `1.17.0+191` —— **清单描述线上版本，不是开发版本**，
  必须等 Release 存在后再改。
- CI：Release 步骤额外 `cp` 一份 `ZY-Player-arm64-latest.apk`，`apkUrl` 用
  `releases/latest/download/…` 后**发版不用再改地址**。
- `test/update_service_test.dart`（新）：flutter_test 写的 21 项断言，覆盖比较/解析/isNewer。

### 踩到的坑
- **Dialog 的返回键**：`showDialog(barrierDismissible:false)` 仍能被返回键 pop，之后代码里再 `Navigator.pop()`
  会多关一层把设置页也关掉 → 两个自动弹出的对话框都包了 `PopScope(canPop:false)`，且只能由调用方 pop。
- **`flutter test` 起不来**：本机沙箱 `Unable to connect to flutter_tester process: WebSocketException
  Invalid WebSocket upgrade request`。改用临时纯 Dart 脚本 `dart run` 验证（21 项全过），跑完删掉；
  正式 test 文件保留（正常环境可跑）。
- 版本名不能按字符串比：`"1.10" < "1.9"`，必须逐段转数字。

### 验证
`dart analyze lib test` → 7 条既有 info，无 error/warning；纯 Dart 脚本 21 项断言全过；
Manifest / file_paths 用 xml 解析器校验通过；Kotlin 改动 grep 复核（analyze 查不到 Java/Kotlin）。

### 遗留 / 注意
- 仓库若是 **private**，raw 与 release 资产都要登录 → 整条更新链路不通，只能换公开托管或自建服务器。
- 发版顺序：改版本号 → 打 tag → CI 出包发 Release → **之后**才改 `update.json`，否则用户点更新 404。
- 本地未推送提交继续累加（现 12 个），`github.com:443` 仍不通。
