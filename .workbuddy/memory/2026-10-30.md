## 新增 GitHub Actions 云端构建 APK（未 push，本地提交 4383aae2）

用户问「如何在 GitHub 上构建这个 APK」，落地为 CI 配置，不是只给方案。

### 关键事实（之前没记，很重要）
- **`android/app/build.gradle.kts` 的 release 用的是 debug 签名**（`signingConfig = signingConfigs.getByName("debug")`），项目里没有自有 keystore，`.gitignore` 也忽略了 `*.jks` / `android/key.properties`。
- 因此本地 release 包的签名来自 `~/.android/debug.keystore`（首次构建自动生成，密码 `android`、别名 `androiddebugkey`）。
- **runner 每次构建都会随机生成一个新的 debug keystore** → 云端包与本地包签名不同 → 手机上装过本地版本就**无法覆盖安装，必须先卸载**。这是 CI 出包最容易踩的坑。
- 解决办法（已做进 workflow，可选）：把本地 `debug.keystore` base64 存 Secret `DEBUG_KEYSTORE_BASE64`，构建前还原到 `$HOME/.android/debug.keystore`，云端包签名即与本地一致；另可配 `DEBUG_KEYSTORE_PASSWORD`（默认 `android`）。未配置时打印 `::notice::` 继续构建。

### 文件
- `.github/workflows/build-apk.yml`：`workflow_dispatch`（input `variant` = split / fat / both）+ `push: tags: v*`。
  - JDK 17（temurin）+ `subosito/flutter-action@v2`（`3.32.6`，`cache: true`）+ `actions/cache@v4` 缓存 `~/.gradle/{caches,wrapper}`
  - 构建前用 `sdkmanager` 补齐 **NDK 27.0.12077973**（`build.gradle.kts` 硬编码，runner 上不一定预装）；compileSdk 平台交给 AGP 自动下载
  - split → `flutter build apk --release --split-per-abi`；fat → `flutter build apk --release`
  - 上传 `actions/upload-artifact@v4`（保留 30 天）；tag 推送时用 `gh release create/upload` 发 Release（`permissions: contents: write`）
  - `timeout-minutes: 60`，首次含 NDK/依赖下载预计 20~30 分钟
- `tools/ci-collect-apk.sh`：按 ABI 把产物重命名为 `ZY-Player-v<版本>-<arm64|armv7|x86_64|universal>.apk`，**幂等**（`[ -f ] && continue`）。之所以抽成脚本并在两次构建后各调一次：`both` 模式下第二次 `flutter build` 可能覆盖 `build/app/outputs/flutter-apk/`，放最后统一收集会丢第一批。
- `.gitattributes` 追加 `*.sh text eol=lf`：本机 `core.autocrlf=true`，CRLF 的 .sh 在 Linux runner 上会报 `$'\r': command not found`。已确认仓库内 `.sh` 与 `.yml` 均为纯 LF。
- README 补「在 GitHub 上构建（GitHub Actions）」一节。
- **CI 配置不进 APK，按惯例不升版本号**（与 `tools/*.bat` 一致），仍 `1.17.0+191`。

### 验证方式（无构建权限，做的是静态/干跑验证）
- PyYAML 解析 workflow 通过（14 个步骤，触发/权限/steps 结构正确）。
- 用本地已有真实产物跑 `tools/ci-collect-apk.sh 1.17.0`：4 个包正确分类（arm64 33M / armv7 27M / universal 69M / x86_64 35M），第二次调用 0 新增（幂等）。
- 版本解析干跑：`1.17.0+191` → name `1.17.0` / code `191`。

workflow 只有 **push 到 GitHub 之后**才出现在 Actions 页面。当前本地领先 `origin/main` **9 个提交**（8 个旧 + 本次 CI），仍未推送 —— `github.com:443` 直连不通的问题未变。

## 改用正式 release 签名（17:10）
用户决定「换正式钥匙」（不再用 debug 签名糊）。做法：
- `keytool` 生成 `C:/Users/Administrator/keystores/zy-player-release.jks`（alias `zyplayer`、RSA2048、validity 10000 天、PKCS12），**放仓库外**，口令随手生成 28 位随机串，写进本机 `android/key.properties`（该文件已被 `android/.gitignore` 忽略）。
- `android/app/build.gradle.kts`：顶部用 `Properties` 读 `rootProject.file("key.properties")`，**先把值取到 `android {}` 外面再赋给 signingConfig**（避免 Kotlin DSL 嵌套 lambda 里 `file()` 解析歧义，用显式 `File(...)`）；`create("release")` 仅在有文件时创建；`buildTypes.release.signingConfig = release ?: debug`。
- workflow：原「恢复 debug.keystore」步骤换成「配置 release 签名」，读 Secret `KEYSTORE_BASE64` / `KEYSTORE_PASSWORD`，解到 `$RUNNER_TEMP/sign/release.jks` 并 `printf` 出 `android/key.properties`，再 `keytool -list` 打印 SHA1；没配 Secret 时输出 `::warning::` 并退回 debug。
- 证书指纹 SHA-1 `BF:DE:D8:E2:9F:5D:86:62:4F:D0:06:45:79:D1:9A:8F:C6:53:F7:7A`（写进 README 备用）。
- 验证：`./gradlew :app:help --offline` 配置通过（只有既有的 fvp compileSdk 36 老警告）；`./gradlew :app:signingReport --offline` 确认 `Variant: release → Config: release → Store: ...zy-player-release.jks`、SHA1 正确；CI 步骤在临时目录干跑（base64 还原字节一致 + keytool 可读）。
- README 签名一节重写；更新记录 1.18.0 加一条「本版改用正式签名，旧版需卸载重装一次」。
