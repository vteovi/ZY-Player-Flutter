## ⚠️ 重要环境发现：Bash 工具传输层把 `\` 转成 `/`

在 Bash 工具命令里写反斜杠字面量（含 heredoc！），到达 bash 时 `D:\WorkBuddy` 变
`D://WorkBuddy`（`b'D:\\W'` len=13、值为 `D://W`，实测实锤）。
**含反斜杠的 python/脚本必须用 Write 工具写成 .py 文件再 `python file.py`，
绝不能内联 heredoc。** 之前桩测试路径替换静默失效就是这个原因（幸好只误写了
真实 tools/build_windows_log.txt 一个日志文件，无实际损失）。

## Windows 第三方播放器修复（commit 9a98cfb）
- 问题：详情页「第三方播放器」走 Android Intent 通道，Windows 无实现 → 'error' toast。
- 修复：`SystemControl.openWithExternalPlayer` 加 `Platform.isWindows` 分支：
  ①reg query App Paths（HKLM/HKCU/WOW6432Node，超时 3s）+ 固定路径探测
  PotPlayer/VLC/mpv/MPC-HC → `Process.start(exe, [url], detached)`；
  ②全未命中 → explorer.exe 交给系统默认关联。
- ⚠️ 本机实测：PotPlayer 装在 `C:/My Program\PotPlayer\`（非标准路径），
  固定路径清单找不到 → **注册表探测是必须的**；App Paths 默认值**带引号存储**，
  解析后必须 strip 引号。reg.exe 输出中文系统是 OEM/GBK → `systemEncoding`。
- reg.exe 在助手沙箱被程序黑名单拦截，运行时行为未实测（真机 app 里没问题）。

## 设置页：从本地 JSON 文件导入 TVBox / ZYFun 配置源（commit a63391a）
- 新增 `lib/services/source_import.dart`：`SourceImport.parse(content)` 解析两种结构：
  - TVBox：`{"sites":[...]}`（数组）
  - ZYFun：`{"sites":{"default":1,"data":[...]}}`（对象，列表在 `data`）
  - 变体：单数 `site` 数组；兼容 BOM、前方广告文字内嵌 JSON
  - type 0=xml / 1=json；2/3/4/7/15(spider/drpy) 需插件 → 跳过（`_mapType` 返回 null）
  - ZYFun 的 status 是布尔 → 转 '可用'/'失效'
- `AppState.importSitesFromContent`：**合并导入**（保留现有源，同名 key 更新），
  返回 `ImportSummary`（added/updated/skipped/format）
- 设置页加「导入配置源 (TVBox/ZYFun)」菜单项：`file_picker` 选 json/txt/conf，
  toast 显示「导入XX成功：新增 N 个，更新 M 个，跳过 K 个需插件的源」
- 依赖 `file_picker`（Android/iOS/Windows 桌面通用文件选择器）
- 与前次 TVBox 链接导入（已回退）不同：文件导入绕开了加密/伪装响应体，直接读明文 JSON。
