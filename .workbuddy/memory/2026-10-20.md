## 设备同步：getLocalIp 显示错误网卡 IP（提交 54734e1）
- 现象：手机开启共享显示 IP 为 10.16.188.58（实为蜂窝数据地址），一体机 Windows 显示 192.168.51.1（实为 Hyper-V/虚拟网卡），都不是路由器网段 192.168.31.x。
- 根因：`LanDiscovery.getLocalIp()` 原逻辑取「首个私有 IPv4 地址」，枚举顺序里蜂窝/VPN/虚拟网卡排在物理网卡前，导致拿了错误 IP 显示（误导手动连接）。
- 修复：`lib/services/sync_service.dart` 新增 `_looksLikePhysicalLan()`，按网卡名排除 rmnet/ccmni/ppp/tun/tap（蜂窝+VPN）、vmnet/vmwre/vbox/vEthernet/hyper-v/docker/br-（虚拟网卡/容器）、bluetooth/pan、zerotier/tailscale/wireguard/openvpn（VPN 隧道），优先返回 Wi-Fi/以太网地址；挑不到再退回首个私有地址兜底（防回归）。
- 说明：自动发现走组播、包里不带 IP（对方从包源反推），故自动发现本就正常；此 bug 仅影响「显示的 IP / 手动填 IP」。
- 版本号 1.12.0+182 → 1.12.1+183（bug fix 升 PATCH，四处同步）。静态检查 7 条既有 info，无 error/warning。
- 本地提交，未 push（push 交用户执行）。

## 播放：部分机型 MediaCodecVideoRenderer error（提交 ffbd62d）
- 报错：`PlatformException(VideoError, ... MediaCodecVideoRenderer error, index=0, format=avc1.640033(H264 High Profile L5.1 1080p), format_supported=YES)`；部分机型偶发。
- 根因：这些机型的硬件解码器在 H.264 High Profile/1080p 渲染阶段抛 MediaCodec 错误（格式本身被支持，解码器实例失败），与源/线路无关。
- 修复：本地 fork `third_party/video_player_android` 的两个 ExoPlayer 构建点（TextureVideoPlayer / PlatformViewVideoPlayer）挂 `DefaultRenderersFactory.setEnableDecoderFallback(true)`——硬解失败时自动回退软件解码器（c2.android.avc.decoder），正常机型仍走硬解、零性能损失。
- 版本号 1.12.1+183 → 1.12.2+184（四处同步）。Java 改动无法 dart analyze，需用户出包验证。
- 备选（若个别机型回退后仍失败）：在设置页加「强制软件解码」开关，用 MediaCodecSelector 优先软件解码器；当前未做，按需再加。
