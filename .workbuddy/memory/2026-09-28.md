## 根因确认：360 安全卫士主动防御拦截命名管道（09:27）

把 Dart `runtime/bin/process_win.cc` 的 `CreatePipes` 逐行复刻成 Python ctypes 脚本
（`%TEMP%\pipeprobe.py` / `pipevariants.py` / `pipename.py`），隔离出唯一失败点：

| 复刻项 | 调用 | 结果 |
|---|---|---|
| stdin 管道 = `kInheritRead` | `CreateNamedPipeW(PIPE_ACCESS_OUTBOUND\|OVERLAPPED)` + `CreateFileW(GENERIC_READ, FILE_READ_ATTRIBUTES\|OVERLAPPED)` | ❌ **恒定 err=231（ERROR_PIPE_BUSY），0/10** |
| stdout/stderr 管道 = `kInheritWrite` | `CreateNamedPipeW(PIPE_ACCESS_INBOUND\|OVERLAPPED)` + `CreateFileW(GENERIC_WRITE, FILE_WRITE_ATTRIBUTES\|OVERLAPPED)` | ✅ 20/20 成功 |

- 与 `OVERLAPPED`、`FILE_*_ATTRIBUTES`、可继承 `SECURITY_ATTRIBUTES`、管道名前缀
  （dart/zzabc/test/mono/a…）**全部无关**；把 `GENERIC_READ` 换成 `GENERIC_READ|GENERIC_WRITE`
  则退化为 err=5（ACCESS_DENIED，方向本身不允许），说明 231 是"读方向被单独拦下"。
- 即：**客户端以 `GENERIC_READ` 连接一个 `PIPE_ACCESS_OUTBOUND` 命名管道，被恒定拦截**。
  这类 API 本身合法（MSDN 规定 OUTBOUND 服务端的客户端就该用 GENERIC_READ）。
- Dart 的 `CreatePipes` 第一步就是 stdin 这条 → 整次 spawn 失败 → `flutter` 全线不可用。
- 为何 Python 不受影响：Python 的 `subprocess` 走**匿名管道** `CreatePipe()`，
  不经过 `\\.\Pipe\` 命名空间。
- 拦截者：`ZhuDongFangYu.exe`（360 主动防御）+ `360FileService.exe` / `360SPService.exe` /
  `360TptMon.exe` / `360tray.exe`（安装于 `C:\Program Files (x86)\360`）。
  这也解释了为什么之前构建能跑 8 分钟——拦截是随 360 启发式/状态后来才生效的。

**解决办法（需要用户操作，脚本无法绕过）**：把 360 主动防御关掉或加白名单，三选一：
1. 托盘右键 360 → 退出（最快，用完再开）；
2. 360 → 防护中心 → 主动防御 → 关闭（或"信任与拦截"里放行）；
3. 360 设置 → 白名单/信任区，加入 `C:\flutter` 与 `D:\WorkBuddy\ZY-Player-Flutter`。

**下次要做的**：解除拦截后，跑 `.workbuddy/tools/wait_and_build_apk.sh`

## 13:05 修「切换比例只是加黑边，画面比例没变」

**现象**：竖屏视频（或任何视频）切到 9:16，只是上下多出黑边，画面内容仍是 16:9。

**根因**：`play_page.dart` 的 `FittedBox` 一直用 `_scaleMode.fit`。默认「适配屏幕」=
`BoxFit.contain`，它**保持视频自身形状**、只在画框内等比缩放 → 画框换成 9:16 只会
多出黑边，内容形状分毫不变。所谓「比例」只改了画框，没改画面。

**修法**：新增 `_effectiveFit`：

```dart
BoxFit get _effectiveFit =>
    (_aspect.ratio != null && _scaleMode.key == 'fit') ? BoxFit.fill : _scaleMode.fit;
```

即：**选了具体比例（非自适应）+ 大小还是默认的「适配屏幕」时，按 `BoxFit.fill` 铺满**
——画面才真的被拉成所选比例的形状；用户显式选「填充/拉伸/原始」时仍尊重其选择。
配套：`_effectiveFitLabel`（面板与诊断块显示实际生效的名称），
比例面板标题改为「画面比例 · 9:16 手机竖屏（画面按该比例铺满）」，
大小面板在固定比例下提示「按拉伸铺满；选填充可改成裁掉边缘」。

## 13:10 「适配屏幕 / 填充 / 拉伸」全部失效 —— 设计缺陷，不是小 bug

**现象**：三种画面大小模式摆出来一模一样，切比例也只是加黑边。

**真正的根因**（比上一轮判断得更深）：`_frameSize()` 让**画面区域本身的形状跟着
比例走**，于是「区域形状 ≡ 内容形状」。FittedBox 在这种盒子里：

- `contain` → 完全吻合，无边
- `cover`  → 完全吻合，无裁剪
- `fill`   → 完全吻合，无变形
- `scaleDown` → 尺寸都小于虚拟尺寸，退化成 contain

四种结果**恒等** → 用户看到的就是"全都失效"。上一轮加的 `_effectiveFit`
只是打了个补丁（把 contain 换成 fill），并没有解决"区域形状 = 内容形状"这个根本矛盾。

**正确的模型**：把「比例」和「大小」拆成两个正交维度。

1. `_stageAreaSize(boxWidth, maxHeight)` —— 画面**区域**的尺寸：
   - 「适配屏幕 / 原始」（要看全）→ 高度按目标比例折算（`boxWidth / ratio`），
     超过可用高度才取满
   - 「填充 / 拉伸」（要铺满）→ 直接占满可用高度
2. `_buildStageContent()` —— **双层 FittedBox**：
   - 内层：纹理盒子 `(natural*1000 × 1000)` 用 `BoxFit.fill` 塞进
     「目标比例形状盒子」（尺寸按 `_displayAspectRatio` 算：`ratio>=1 ? (r*1000,1000)
     : (1000, 1000/r)`）→ 实现"画面真的变成所选比例的形状"
   - 外层：形状盒子按 `_scaleMode.fit` 放进画面区域 → 此时四种 fit 结果各不相同

**行为矩阵**（自适应 = 目标形状就是视频原始形状）：

| 大小 ＼ 区域 | 适配屏幕 | 填充 | 拉伸 |
|---|---|---|---|
| 自适应 16:9 | 区域=16:9，吻合无边 | 区域占满高，左右裁切 | 区域占满高，变形铺满 |
| 9:16 | 区域封顶，两侧黑边 | 竖内容铺满区域 | 竖内容变形铺满 |

顺带删除 `_effectiveFit` / `_effectiveFitLabel`，`_buildVideoArea` 改收 `Size area`
（不再需要单独传 boxWidth + Center）。

## 14:15 全屏下返回键：先退全屏，再返回才退出播放页

`lib/pages/play_page.dart` 的 `build` 用 `PopScope` 包住 `Scaffold`：

```dart
PopScope(
  canPop: !_fullscreen,
  onPopInvokedWithResult: (didPop, result) {
    if (didPop || !_fullscreen) return;
    _toggleFullscreen();
  },
  child: Scaffold(...),
)
```

**要点（容易踩）**：
- 用 `PopScope` 而非 `WillPopScope`（后者已废弃，且不支持预测式返回手势）
- `canPop` **在 build 时求值**：第一次返回时 `canPop=false` → 回调把 `_fullscreen`
  置 false → 重建后 `canPop=true` → 第二次返回才真正 pop。**不需要**手动计数。
- ⚠️ 拦截分支里**不要**自己调 `Navigator.pop()`。系统已经决定「不 pop」，
  再手动 pop 会重复出栈，直接把播放页也弹掉。
- 副作用：`canPop=false` 期间 iOS 的边缘滑动返回也被禁用（全屏时符合预期）。
- `_toggleFullscreen()` 已经负责把方向复位成竖屏 + 退出沉浸式 + 收面板，
  所以退出全屏后状态是干净的，不用额外处理。

校验：单进程 analyzer → `files: 21  errors: 0  warnings: 0  lints: 0`

**⚠️ versionCode 不能用 100**：0.1.3 是 103，Android 要求 versionCode 严格递增，
否则覆盖安装会失败（"应用未安装"）。所以 `1.0.0` 配 **104**。

**`tools/build_apk.bat` 改成从 pubspec 自动取版本**（原来写死 `-v0.1.3-`）：
```bat
set "APPVER="
for /f "tokens=2" %%V in ('findstr /b /c:"version:" "%PROJ%\pubspec.yaml"') do set "APPVER=%%V"
if not defined APPVER set "APPVER=0.0.0+0"
for /f "tokens=1 delims=+" %%B in ("%APPVER%") do set "APPVER=%%B"
set "OUT=%PROJ%\ZY-Player-v%APPVER%-arm64-release.apk"
```
要点：
- `findstr /b` 只匹配**行首**，所以 pubspec 里 `# ... versionName 0.1.2 ...` 注释行不会误配
- `for /f` 读 LF-only 文件（pubspec 是 LF）实测正常，取值干净无 `\r`
- 两个 `for` 都在**顶层**，读 `%APPVER%` 不需要 `EnableDelayedExpansion`
- 头部新增 `echo   Version: %APPVER%`，双击后一眼能看到这次编的是哪版

## ⚠️ 离线 Kotlin 校验（MainActivity.kt）新踩的坑 —— 已修并已固化进 compile_kotlin.sh

离线编译脚本 `.workbuddy/tools/compile_kotlin.sh` 之前能跑通 Java，但对 kotlin 有 3 个连环坑，
这次全踩全修，已 commit（a79ec84）：

1. **Kotlin 块注释可嵌套（最阴）**：在 KDoc 里写 `` `video/*` `` 这种字面量，会**多开一层**块注释，
   后面那个 `*/` 只关掉内层，外层一直不闭合 → 整个文件后半段被当注释吞掉，表现就是
   「一堆 `unresolved reference 'getScreenBrightness'` + 结尾 `Unclosed comment` + `Missing '}'`」。
   **规则：注释里绝不出现 `/*` 与 `*/` 字面量**，用中文「斜杠加星号」描述。这个 bug 会直接炸 Gradle。
   （字符串字面量 `"video/*"` 不受影响，只有出现在注释里才触发。）
2. **Gradle 缓存产物层级**：真实路径是 `group/artifact/版本号/哈希/文件`，find 必须
   `-maxdepth 2`，原脚本 `-maxdepth 1` 永远找不到 → androidx 的 aar/jar 全 0 解出 →
   误导性报「cannot access LifecycleOwner which is a supertype of FlutterActivity」。
3. **编译器自身缺件**：后端 IR codegen 要给参数写 `@NotNull`，需 `org.jetbrains:annotations`
   在**编译器 classpath**（`CPC`）上；缺了会「前端全过、codegen 阶段抛
   `BackendException: Exception during IR lowering` → `NoClassDefFoundError: org/jetbrains/annotations/NotNull`」，
   极像代码问题，其实是工具链缺 jar。

**经验**：离线 kotlinc 必须 `dangerouslyDisableSandbox: true` 跑 —— 否则 Java 进程被沙箱掐掉，
连 `echo` 都不输出（stdout 全空，exit 0）。已验证 `KOTLIN_COMPILE_OK`（1 class）。
Dart 侧用单进程 analyzer（`%TEMP%\zyanalyze\analyze.dart`，从工程目录跑）同样需关沙箱，结果 0/0/0。
