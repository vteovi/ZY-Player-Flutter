## feat v1.26.0：全屏双指上下滑调倍速（commit `0f2757de`，dev，未推送）
- 需求原话：「在播放页面全屏播放的时候，帮我再增加一个快捷手势：双指上滑增加播放速度，双指下滑减少播放速度。」

### 关键结论（技术选型，别重走弯路）
- **`GestureDetector` 不能在同一层同时挂 scale 和 vertical/horizontal drag**：Flutter 的 `GestureDetector.build` 里有断言，scale 是 pan/vertical/horizontal 的超集，同时存在直接 `FlutterError`（"redundant; scale is a superset of ..."）。所以「用 onScaleUpdate 的 pointerCount 判断双指」这条路走不通，除非把整套单指手势改写成 scale 手动分流（改动大、风险高）。
- **最终方案：`Listener` 旁听原始指针事件**。Listener 不参与手势竞技场，只多拿一份 pointer 流水，单指那套识别器完全不受影响：
  - `Map<int, Offset> _pointers`：pointer id → localPosition，用来数手指数 + 算双指平均 Y（两指不可能同步，取平均比只盯第一根稳）。
  - 第 2 根手指 down → `_beginSpeedGesture()`；两指移动 → `_updateSpeedGesture()`；`_pointers.length < 2` → `_endSpeedGesture()`。
  - hit test 顺序：子（GestureDetector 的 recognizer）先收事件、父（Listener）后收。所以双指 down 时 drag 可能已 addPointer，但 drag 的 start 要等移动超过 slop，此时 Listener 已把 `_pointers` 填好，`onVerticalDragStart/Update` 里 `if (_pointers.length >= 2) return;` 能拦住。
- **Listener 的回调签名会推断事件类型**，所以方法只收 `(int pointer, Offset position)`，不用额外 `import 'package:flutter/gestures.dart'`（`PointerDownEvent` 等不一定被 material 间接导出）。

### 实现要点
- 档位复用 `_kSpeedOptions`（0.5 / 0.75 / 1.0 / 1.25 / 1.5 / 2.0 / 2.5 / 3.0），通过 `_selectSpeed()` 落地，与倍速面板共用一条路径。
- `_kSpeedGestureStep = 80.0` + `round()` → 实际约 40 逻辑像素跳一档；从 1.0 到 3.0 需 5 档 ≈ 200px，短屏（横屏全屏高约 390）也滑得满。
- **按「相对起点」换算而不是累计增量**：`steps = ((startY - avgY) / step).round()`，滑过头能往回修正，手指抖动不会一路漂到顶。
- **`num.clamp` 返回 `num`，不能直接当 List 下标**，必须 `.toInt()`（这个坑编译期才发现，本机无 Dart SDK 只能靠 CI analyze）。
- 第 2 指落下时把另外三个手势一并作废：亮度/音量（`_gestureActive = false`，**停在当前值不回滚**，回滚会像「滑一半自己弹回」）、横向 seek（`_onSeekEnd()`）、长按加速（`_onLongPressEnd()`）。否则三个手势会同时改同一个播放器。
- HUD：`_buildSpeedGestureHud()` 居中显示当前倍速 + 「双指上滑加速 · 下滑减速」，到 0.5×/3.0× 显示「已是最慢/最快」。
- 复位点：`_toggleFullscreen`（切屏）、`_switchEpisode`（换集）、`dispose` 三处都 `_pointers.clear()` + 清 `_speedGestureStartY`。
- 只做全屏：`_buildGestureLayer` 里 `if (!_fullscreen) return gesture;` 才包 Listener，竖屏不挂（`_pointers` 恒空，`>= 2` 永假，单指行为零变化）。
