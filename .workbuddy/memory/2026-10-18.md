## box.iqinu.com 导入失败修复：按 UA 分发 + TVBox 加密配置（1.11.1+181）
- 用户指出 `https://box.iqinu.com` 在 TVBox 里可用，参考项目 `D:/Project/TVBoxOS_Portrait-main`。
- **根因两条**：
  1. 站点**按 UA 分发**：`okhttp/*` 才返回真配置（67662 字节 hex），浏览器 UA 拿到 623 字节「恭喜，站点创建成功！」占位 HTML。TVBox 的 `ApiConfig.userAgent = "okhttp/3.15"` + Accept 头。
  2. 正文是 **TVBox 加密配置**：hex 解码后为 `$#<key>#$ <AES-128-CBC 密文> <13 字节 IV>`，key/iv 都用 `'0'` 右补到 16。算法见 `ApiConfig.FindResult()`（`content.startsWith("2423")` 分支）。IV 是 13 位 ASCII 数字串（如 `1784554329848`），所以 Java 用 `new String(bytes)` 再取末 13 字符能work。
- **实现**：新增 `lib/utils/tvbox_crypto.dart`：`TvBoxCrypto.decode()` + 纯 Dart `AesCbc.decrypt()`（只实现解密，S 盒用 GF(2^8) 求逆+仿射变换算法生成，避免手抄 256 字节表）。**不引入 pointycastle**（本地 pub cache 没有，构建要联网）。
- **坑**：GF 求逆要**幂运算**（x^254），我一开始写成 `_gmul(x, 254)`（等于"乘 254"）→ 解密全是乱码。用 NIST SP 800-38A 向量（key 2b7e... plaintext 6bc1...）才定位到。
- **验证**：Dart 解密结果与 `openssl enc -d -aes-128-cbc -K ... -iv ...` 输出逐字符一致（25359 字符）；82 条 sites → 导入 41 个 maccms 源（另 41 个 type=3 spider 跳过），抽检 6 个源全部 ok。
- `HttpService._fetchConfig`：UA 依次 `okhttp/3.15` → `okhttp/3.12.0` → 浏览器，返回第一个 `_looksLikeConfigPayload`（JSON / `2423`+`$#` / 长非 HTML 文本）；全是网页时保留 HTML 给导航页流程。
- `SourceImport` 收紧：`_resolveApi` 对 `api/url` 字段也过滤 `_looksLikeAssetUrl`（`.js/.json/.txt/.yaml` 结尾、逗号多域名），`ext` 兜底只收 `_looksLikeMaccmsApi`（含 api/.php/provide/vod 且无逗号）。否则 `drpy_js_*`（api 直接指向 `drpy.min.js`）会被导成坏源。
- 版本 1.11.0+180 → 1.11.1+181（fix，PATCH 升）。已提交 `8b6bad67`，分支 `feature/tvbox-import`，工作区干净，未 push。
