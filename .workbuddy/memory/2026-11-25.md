## v1.35.0 瀑布流显示模式（dev，未推送）
- 用户：「增加一个瀑布流显示模式，按海报图实际比例显示、不裁切；手机两列，平板按宽度决定列数」。

- 核心难点：**maccms 接口只有图片 URL，没有尺寸**，而瀑布流必须提前知道每张海报的高宽比才能布局。三条获取路径（成本从低到高，见 `lib/utils/poster_ratio.dart` 文件头注释）：
  1. 内存命中；2. 落盘索引 `poster_ratio.json`；3. **读图片文件头（前 64KB）解析宽高，不解码像素**。
- `lib/utils/poster_ratio.dart`（新增）：
  - `_parseHeader` 支持 JPEG（遍历段找 SOF，排除 C4/C8/CC）、PNG（IHDR）、GIF、WebP（VP8/VP8L/VP8X 三种子格式）。
  - `remember` 防抖写盘 900ms；`revision`（ValueNotifier）**节流 220ms** 才 +1，避免一屏几十张图逐条 setState 抖动。
  - `measureFromFile`（读文件头，`_measuring` 去重）+ `beginProbe/endProbe`（等解码回调，`_probing` 去重）。
  - 比例合理性校验：`> 0.2 && < 5`，越界丢弃（防解析出垃圾值把卡片拉成一条线）。
- 尺寸从哪来（两条**零额外成本**的路径）：
  1. `ImagePrefetch.prefetch` 拿到落盘 File 后顺手 `measureFromFile`（首页，本来就要下载）；
  2. `PosterCover` 网络分支加 `imageBuilder`，对**同一个 provider** 再 resolve 一次读像素尺寸 —— 共享 ImageCache 条目，**不重复下载、不重复解码**；`Image.file` 分支直接 `measureFromFile`。搜索页/收藏/历史没预取，靠这条。
  - ⚠️ 自定义 `imageBuilder` 会**丢掉 CachedNetworkImage 自带的淡入**，所以自己用 `frameBuilder` + `AnimatedOpacity(300ms)` 补回来了。
- `lib/widgets/waterfall_grid.dart`（新增）：
  - `waterfallColumnCount`：`width < 600 → 2`；否则 `(width / 190).floor().clamp(2, 8)`。用 floor 不用 round（宁可列多、卡小，也不要一张胖海报把行撑歪）。
  - `WaterfallGrid` 用 `CustomScrollView` + `SliverMasonryGrid`（**不是** `MasonryGridView`），理由有二：能关 `addAutomaticKeepAlives`（与网格模式一致，长列表不膨胀）；能在末尾挂**横跨整行**的加载更多指示器（MasonryGridView 只能占一格）。`SliverMasonryGrid.count` 没有这个参数，得用主构造传 `SliverChildBuilderDelegate`。
  - `waterfallCoverRatio(pic)`：有比例用比例，没有就用 `fallback = 2/3` 占位并顺手触发 measure。
- 卡片改动：`VideoCard` / `RecordCard` 新增 `coverRatio`（null = 网格模式用 `Expanded` 撑满；非 null = 瀑布流用 `AspectRatio` 定高）。比例准了 `BoxFit.cover` 就不裁切。
