# 2026-10-17 工作日志

## 修复横屏下片单「打开就已经到底、上滑滑不动」（1.9.18+172，commit f49b813d）
- 用户报：横屏模式下，打开后列表默认就已经到底，不再往下加载；上滑没反应、新内容不显示，
  只有左右滑（切分类）能用。
- 根因：`CategoryTabState` 的「加载更多」只挂在 `_onScroll`（滚到底部附近）上。横屏 / 平板 /
  大屏时列数变多、行数变少，首屏那 6 条（`_refresh` 至少凑 6 条）可能**整屏放得下** →
  `GridView.maxScrollExtent == 0` → **产生不了任何滚动事件** → `_loadMore` 永不触发。
  不是网络问题，是「内容不满一屏就永远触发不了翻页」的经典死局。
- 改法（`lib/pages/film_page.dart`，只此一处，其他列表无分页）：
  1. 新增 `_maybeContinueLoad()`：`addPostFrameCallback` 里检查，若
     `maxScrollExtent <= 0`（不可滚动）或 `pixels >= maxScrollExtent - 400`（仍贴底），
     且 `_pageCount > 1`、未在加载，就主动 `_loadMore()`。
  2. `_loadMore` 成功后不再用旧的「立即检查 `position`」（此时布局还没更新，extent 是旧值），
     统一改走 `_maybeContinueLoad()` 的下一帧检查 —— 到底即连续加载。
  3. `_refresh()` 结束也调一次：首屏就撑不满时立即补页。
  4. `CategoryTabState` 加 `WidgetsBindingObserver`，`didChangeMetrics`（旋转 / 分屏）
     触发重新补齐 —— 竖屏转横屏后内容可能不再溢出，同样会卡。
  5. 死循环兜底 `_noGrowStreak`：连续两页列表没增长（源站返回重复 id）就停止续拉，
     避免对问题源空转狂刷。
- 静态检查无 error / warning，仅 5 条既有 info。版本 1.9.17+171 → 1.9.18+172（四处同步）。
