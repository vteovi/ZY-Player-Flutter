## 源管理「检测全部」提速（14:50）
用户反馈检测全部不够快，问能不能多线程。**Dart 单线程但 HTTP 是异步 IO，多并发就是真并行**，不需要 isolate。
- 实测（python 绕代理、浏览器 UA、`?ac=list`）：11 个内置源单请求中位 **1.4s**、最慢 3.4s、串行合计 18.6s；**并发 4 约 12s / 并发 8 约 4s / 并发 100 反而 10.8s**（目标站限流 + 本机小水管）。甜点 = 8。
- **注意**：这一批采集站的尾部延迟抖动很大，同一并发度两次跑能差到 4s vs 12s（偶发一个请求卡满超时）。所以「并发」只解决平均值，超时长度决定最坏情况。
- 改动：
  1. `site_page.dart`：并发 4 → `_checkConcurrency = 8`（`min(8, 组数)`）。
  2. **按接口归组去重**：新增 `_probeKey(site)` = `scheme://host+path`（查询串不参与），同组只 `checkSite(group.first)` 一次，结果套给全组，`_done += group.length` 保持进度正确。第三方配置里「一个 api.php 派生十几个源」很常见，这条收益最大。空 api 用 `empty:{key}` 各自独立，无 scheme 走 `raw:$api`。已用临时 dart 脚本验证分组合并正确。
  3. 批量检测时把组内源加入 `_busy`，条目上显示「检测中…」（原来批量检测不标记，界面一片「未检测」）。
  4. `http_service.dart`：新增 `static final http.Client _client`，`_fetch` 与 `_fetchConfigWithUa` 由顶层 `http.get/post` 改用它 —— 顶层函数每次新建 client 再 close，等于每个请求从零握手；共享后可命中 keep-alive + DNS 缓存（同域名只解析一次）。**不要 close**，空闲连接由 idleTimeout 回收。
  5. `_checkTimeout` 8s → **6s**（实测中位 1.4s、最慢 3.4s，留近一倍余量；死站卡 SYN 时省一轮）。
  6. `checkSite`：`payload.looksLikeHtml` 时**跳过裸地址回退** —— 带 `ac=list` 就返回网页说明接口路径整体换了，换裸地址只会再白等一个超时。
- 版本 **1.19.2+199**（v1.19.1 已于 10-31 02:15 发布，198 占用）；`update.json` 同步到 1.19.1/198。
- `dart analyze lib` 仍只剩 7 条历史 info，零新增。
