## main(=1.9.8) 上修复内置播放器「播放失败」
- 用户报：部分影片内置播放报「播放失败，请更换视频源或线路」，但外部播放器能播。

  **没传 httpHeaders**，ExoPlayer/2.x 的 UA 被很多源站/CDN 按 UA 拦截
  （403 或返回 HTML 而非视频流）→ 初始化失败、外部用自己的 UA 能过。
- 改动（play_page.dart，提交 `ccc456e`）：
  1. 两处创建控制器（init / 换集）补浏览器 UA 头 `_kPlayerHeaders`。
  2. 把被 `catch (_)` 吞掉的异常暴露：`_lastError` 存真实错误，失败界面显示
     ExoPlayer 的 `errorDescription`，便于区分 403 / mime / codec。
  3. 失败界面加「用外部播放器打开」兜底按钮（与外部播放入口同逻辑）。
- 版本 1.9.8+156 -> 1.9.8+157（保持 1.9.8 名，构建号严格递增）。
- ⚠️ 未实测（构建由用户做）：UA 修复命中率最高；若是 HLS/编码不支持仍可能失败，
  届时看失败界面新显示的真实错误再定。完整当天日志在分支 `v1.9.12`

## main 上支持 Windows 桌面端「模拟画中画」(PiP)
- 用户问 Windows 版不支持画中画能否支持。结论：Windows 无系统级 PiP API，
  但可用「主窗变置顶无边框小浮窗」模拟——fvp 视频渲染进 Flutter Texture，
  主窗缩小视频即随之缩小，浮于其他窗口之上。
- 根因：画中画原仅 Android 实现（`com.zy.player/pip` 通道只在 `MainActivity.kt`
  注册），Windows 端没注册 `enterPip`，Dart 调它直接走 catch 报"不支持"。
- 改动（提交 `1cc0f1a`，版本 1.9.13+159）：
  - `windows/runner/win32_window.{h,cpp}`：新增 `EnterPip/ExitPip/IsInPip`；
    进入时保存窗口样式+位置/尺寸、置顶(`HWND_TOPMOST`)、去标题栏(`WS_POPUP`)
    +保留可缩放边缘(`WS_THICKFRAME`)、按宽高比缩到 360 逻辑宽小窗贴右下角；
    退出精确还原。`WM_NCHITTEST` 让无标题客户区可拖动、边缘可缩放。
  - `windows/runner/flutter_window.{h,cpp}`：注册与 Android 同名 `com.zy.player/pip`
    通道，处理 `enterPip/exitPip` 并回传 `onPipModeChanged` 事件。
  - `lib/pages/play_page.dart`：`_buildPipBody` 在桌面端叠加退出按钮 + 双击退出
    （`isDesktop` 判断，Android 仍走系统 PiP 不需要）；新增 `_exitPip`。
- ⚠️ C++ 改动未在本机静态检查（需 MSVC），逻辑已 review；Windows 构建由用户做，

## 修复 Windows 构建失败（C++ 编译错误，提交 `fa9e7be`，版本 1.9.13+161）
- 用户首次在该分支出 Windows 包报 BUILD_FAILED，日志两类错：
  1. C2039 `GetBinaryMessenger` 不是 `flutter::FlutterEngine` 成员：Flutter 3.32
     embedding 取 BinaryMessenger 要用 `engine()->messenger()`，不是
     `GetBinaryMessenger()`。两处（`pip`/`window` 通道）已改。
  2. C2039 `StandardMethodCodec` 不是 `flutter` 成员：`method_channel.h` 未包含
     `standard_method_codec.h`，已在 `flutter_window.h` 补 `#include`。
  3. C4819→C2220（/WX 把警告当错误）：4 个 runner C++ 文件里我加的中文注释是
     UTF-8 无 BOM，MSVC 按 GBK(936) 读报"无法表示"。已把全部中文注释改英文，
     文件非 ASCII 字符数归零。
- 教训：本仓库 Windows 原生代码**不能写中文注释**（除非带 UTF-8 BOM 且能保证不被
  工具重写丢 BOM）。下次改 C++ 一律用英文注释。
- Dart 端已确认 `play_page.dart:204` 注册了 `setMethodCallHandler(_onPipCall)`、
  `:424` 处理 `onPipModeChanged`，原生回传事件链路通，PiP 功能闭环。
- 二次构建仍报错 C2665：4 处 `result->Success(std::make_unique<EncodableValue>(true))`
  误传 unique_ptr，但 `MethodResult<T>::Success` 接收 `const T&`。改为
  `result->Success(flutter::EncodableValue(true))` 直接传值（提交 `c0cd9d2`，版本 +162）。
  `InvokeMethod` 仍用 `make_unique` 符合其 API，保持不变。

## 修复 Windows PiP 与全屏 bug（提交 `a82ff2c`，版本 1.9.14+164）
- 用户实测反馈：
  1. PiP 小窗显示"半个标题栏"，且不能移动/还原/关闭。
  2. 全屏时窗口"卡住"（死锁/卡死）。
- PiP 根因+修法：原 `WS_POPUP|WS_THICKFRAME|WS_SYSMENU` 组合会画出残缺标题栏，
  且 WS_POPUP 无真正标题栏→无法拖动/关闭。改为 `WS_CAPTION|WS_THICKFRAME|
  WS_SYSMENU`（完整可用标题栏），原生即可拖动/关闭/还原；补 `SWP_FRAMECHANGED`
  强制重算非客户区消除残留像素。桌面端去掉会被标题栏盖住的 Flutter 关闭按钮，
  改用原生标题栏 X 关闭（新增 `WM_CLOSE` 拦截：关闭时还原窗口而非退出 App），
  保留双击视频退出。
- 全屏根因+修法（卡死真因）：在 Flutter method-channel 回调里**同步**调用
  `SetWindowPos` 改变窗口大小时，会重入引擎的 `WM_SIZE` 处理，UI 线程死锁。
  改为把实际样式/尺寸变更 `PostMessage` 到消息循环**延迟执行**
  （`ApplyPipEnter/Exit`、`ApplyFullscreenEnter/Exit`，自定义消息 WM_APP+1/+2），
  避免重入死锁。两个通道的 enter/exit 全部延迟应用。全屏同样补 `WM_CLOSE` 拦截。
- 教训：Flutter 桌面端**不要在 method-channel 回调里同步改窗口尺寸/样式**，
  必须延迟到消息循环，否则大尺寸变更（如全屏）会死锁卡死。
- ⚠️ C++ 仍需用户 Windows 构建验证（本机无 MSVC）。

## 修复「画中画退不出」+ 三个模式互相干扰（提交 `8665530`，版本 1.9.14+165）
- 用户实测：进画中画后**退不出来**；且画中画/填满/全屏"三个功能好像都一样"。
- 根因1（退不出）：上一版把窗口变更延迟到消息循环后，`ExitPip`/`ExitFullscreen`
  忘了把 `pending_*` 设成 `kExit`，延迟处理器看到 `kNone` 就什么都不做 → 窗口
  永远还原不了。修复：Exit 里补 `pending_pip_=kExit` / `pending_fs_=kExit`。
- 根因2（三个都一样）：根因1 导致一旦进过某模式就卡在那，点别的按钮只改 Dart
  标志、窗口不动，看起来自然一样。修根因1 即解。
- 顺带修延迟模型缺陷：原 `EnterPip/EnterFullscreen` 存"当前"窗口几何，从另一
  特殊模式切过来会存错、退出还原错。改为只在**从普通态进入**时记一次
  `normal_style_/normal_rect_`，两模式互斥（进对方时清自己），退出统一还原普通态。
  头文件删掉 `saved_style_/saved_rect_/saved_fs_style_/saved_fs_rect_`，换单一对。
- Dart：`_enterPip` 进入时同步清 `_nativeFullscreen`。
- `.gitignore` 加 `*.zip`（Windows 构建产物原来没被忽略）。
- ⚠️ C++ 仍需用户 Windows 构建验证。

## 修复 Windows 全屏/画中画「整个程序无响应」+ 原生诊断日志（提交 `e629a5f`，版本 1.9.14+166）
- 用户实测（用的是最新构建）：点「全屏」和「画中画」都会**整个程序无响应**
  （只能任务管理器强退）。询问确认：是硬死锁，不是画面卡住。
- 定位（排除法）：只有「填满」正常（纯 Flutter 布局 + SystemChrome），
  而「全屏」「画中画」都要改**原生窗口样式+尺寸**，且都死锁 → 卡点在原生窗口变更。
  翻 fvp 源码（`pub.dev\fvp-0.38.1\windows\fvp_plugin.cpp`）证实 Windows 上
  `TexturePlayer` 用 **D3D11 共享纹理**输出：`ObtainDescriptorCallback`（光栅线程）
  持 `mtx` 做 `CopyResource`+`Flush`，mdk 渲染回调（渲染线程）持同一 `mtx` 调
  `MarkTextureFrameAvailable`。视频出帧时改窗口尺寸 → 引擎重建渲染表面与插件
  纹理回调相互等待 → UI 线程锁死。同步/延迟（PostMessage）两种写法都会死锁。
- 改动：
  1. **Dart 侧「摘纹理」过渡**（关键修法）：改窗口前把 `Texture` 从控件树摘掉
     （`_windowSwitching` → `_buildStage` 换同尺寸黑盒），等 `endOfFrame` 两帧 +
     60ms 再调原生；原生 `PostMessage` 是异步的，所以调用后**再等 250ms** 才挂回
     纹理。统一封装 `_withVideoDetached()`。播放不中断，音频继续。
  2. 原生改窗口改为**在现有样式上增删位**（保留 WS_VISIBLE/WS_CLIPCHILDREN 等，
     此前是直接赋 `WS_POPUP`/`WS_CAPTION|…` 整个替换），并用**单次**
     `SetWindowPos(位置+尺寸, SWP_FRAMECHANGED|SWP_NOOWNERZORDER|SWP_NOACTIVATE)`
     —— 与 window_manager 插件的写法一致（此前是两次 SetWindowPos）。
  3. **原生不再自己改窗口退出**：PiP/全屏下点标题栏 X / Alt+F4 → `WM_CLOSE` 只回传
     `onPipExitRequested` / `onFullscreenExitRequested` 请 Dart 退出（返回 0 不销毁），
     这样退出也能先摘纹理。此前原生自行还原会让 Dart 停在「只剩视频、无控件」死状态。
  4. Dart：注册 `com.zy.player/window` 的 `CallMethodCallHandler`（`_onWindowCall`）；
     进原生全屏后强制 `_controlsVisible=true` 并重排自动隐藏（保证「退出全屏」按钮
     一定可见）；桌面 PiP 画面右上角加回兜底退出按钮；桌面不再调无实现的
     SystemChrome 方向/沉浸接口（免 MissingPluginException）；新增
     `_windowChangeBusy` 防重入。
  5. **原生诊断日志**：`<exe目录>\zy_player_debug.log`（`Win32Window::Trace` /
     `TraceReset`，启动时截断）。逐条记录 WM_SIZE/WM_NCCALCSIZE/
     WM_WINDOWPOSCHANGING(ED)/WM_SHOWWINDOW/WM_STYLECHANGED/WM_CLOSE 等、是否被引擎
     `HandleTopLevelWindowProc` 消费、以及 `Apply*` 每一步。**若仍卡住，日志最后
     一行就是卡住的那一步**，据此可精确定位。
- ⚠️ 本机无 MSVC，C++ 无法编译验证；已确保 4 个 runner 文件仍为纯 ASCII（防 C4819）。
- 建议用户顺带测：播放中**拖动窗口边框改大小**会不会也卡 —— 若会，说明是「视频
  出帧时改窗口」这条路径本身的问题（已由第 1 条缓解），若不会则说明卡得更靠后。
