## 修复首页片单永远显示同一批老片（commit 5de81d1，1.24.1+209，dev）
- 用户反馈：「加载一个网站之后，每个分栏下的内容永远都是同一批海报，从来没更新过」。
- **根因（严重，存在很久）**：maccms 采集接口 **`pg=1` 才是最新**，页码越大越老。实测极速源 `pg=1` 是当天 21:18 更新的片子、`pg=5863`（末页）是 2023-05-03 的。但 `CategoryTab._refresh()` 从 `info.pagecount` 开始取，所以每个分类拿到的都是**全站最老那一批**，老片不会变 → 永远同一批海报。`_load()` 的缓存恢复同样读 `[pagecount, pagecount-1]`。
- **验证方法（以后怀疑分页方向就这么查）**：直接 curl 源站 `${api}?ac=videolist&pg=1` 与 `pg=<pagecount>`，比对 `vod_time`；不用装 App。
- 修复：`_pageCount` 语义从「递减到 1」改成「递增到 pagecount」，新增 `_totalPages`；`_refresh` 从 1 开始取、`_loadMore/_warmUp` 递增、`_maybeContinueLoad` 的终止条件改成 `_pageCount > _totalPages`；缓存恢复改读第 1、2 页。
- 刷新取数加了 **3 页上限**：`fresh.length < 6` 在源站返回空列表（不报错）时会一直成立，没有上限会朝几千页的源空打几千次请求。
- `ListCache` 加缓存版本 `_cacheVersion = 2`：升级后整体清空 listcache 一次（旧 key 存的就是老片）。⚠️ 版本校验用 **`Future?` 缓存而不是 bool 标记** —— 首页多个分栏并发初始化时，bool 会在清理还没跑完就置真，后面的分栏直接读到即将被删的旧缓存。
- 第二个问题：首页用 `IndexedStack` + `AutomaticKeepAlive` 常驻，切到收藏/设置再回来不会重建，`_load()` 只跑一次 → 内容永远停在打开那一刻。加了「刷新令牌」机制：`FilmPageState._refreshTicks[tid]++` → `CategoryTab.refreshTick` 变化 → `didUpdateWidget` 里静默 `_refresh()`。只给当前可见分类加，避免回前台时朝源站打十几个并发请求。触发时机：`didChangeAppLifecycleState == resumed`、`reloadIfNeeded()` 签名未变时，阈值 10 分钟（`_staleAfter`）。
- 第三个问题：`fetchPage` 内部 catch 返回 `const PageInfo()`，pagecount=1 → 被当成「真的只有一页」写进缓存 meta，该分类之后再也翻不动。给 `PageInfo` 加 `ok` 标记（失败 `PageInfo(ok: false)`），`_doRefresh` 遇到 `!info.ok` 就**不写缓存、不动 `_totalPages`**，保留现有内容；手上一条数据都没有时显示带「重试」的 `EmptyHint`。
- 版本 fix → PATCH：1.24.0+208 → **1.24.1+209**（pubspec + local.properties）。本机无 Dart，**未 push**，等 CI analyze。

## 修复 v1.24.1 首页各分类全部「暂无资源」（commit ba2674e，1.24.2+210，dev）
- 用户反馈：v1.24.1 发布后「网站加载成功后，各个分类下面都会显示该分类下暂无资源」。
- **实测排查过程（有用，记下来）**：
  - 批量 curl 内置源对比 `?ac=videolist`（fetchPage 用的）/ `?ac=videolist&pg=1`（fetchList 用的）/ `?ac=videolist&pg=<pagecount>`：能通的源三者都正常（20 条），**排除「pg=1 返回空」**。
  - 用 `?ac=list` 拿真实分类再测：**父分类（如「连续剧」）`t=<tid>` 会返回 `pagecount=0, total=0, list=[]`**，只有子分类（如「动作片」）才有数据。这是源站行为，新旧版都会空，不是本次回归。
  - 关键代码路径：`videos.isEmpty` → `video_grid.dart` 的「该分类下暂无资源」。走到这里说明 `_loading=false` 且 `_loadFailed=false`，即 `_doRefresh` 正常走完、但 `fresh` 为空且没有旧内容。
  - 结论：**要么 `_appendPage` 抛异常（网络/限流/写缓存），要么 fetchList 返回空**。旧版取末页只有 2 个请求/栏、且缓存有兜底；v1.24.1 每栏最多 3 页 + warmUp 2 页，首页十几个分类同时初始化叠成几十个并发，再叠加「首次启动缓存被 `_cacheVersion=2` 清空」，失败就直接显示成「暂无资源」，把网络问题伪装成源站没内容。
- 修复（全部是「失败要可见 + 缓存不拖累显示」方向）：
  - `_doRefresh` 加 `anyOk`：**区分「全部请求失败」与「源站真没内容」**，前者 `_loadFailed=true` 给「片单加载失败 + 重试」，不再静默显示「暂无资源」。
  - 首屏只取 1 页（`tries < 2`）、`_warmUp` 从立即 2 页改成延迟 700ms 只垫 1 页，压并发峰值。
  - `_appendPage` 空页自动重试一次（350ms）；**`putPage` 移到数据入列表之后且 try/catch 吞掉** —— 以前写缓存一抛，刚取到的整页连同循环一起作废。
  - `pagecount <= 0` 时 `lastPage=1`，至少试第 1 页（以前 `page <= 0` 一次都不循环）。
  - `_load()` 读缓存全程 try/catch，异常降级为「无缓存继续走网络」；有 meta 无分页缓存时 `_loading = true` 继续骨架屏，不先闪「暂无资源」。
  - `ListCache._ensureVersion` 失败不再永久缓存 error Future（用 `then(onError:)` 清空 `_versionReady` 重试）—— 否则一次失败会让所有分栏在 `getMeta` 处永久抛。
  - 「该分类下暂无资源」补「刷新」按钮（`_retryLoad`），用户可自查是不是网络问题。
- 版本 fix → PATCH：1.24.1+209 → **1.24.2+210**。dev push 时 github.com 又整段不通约 6 分钟（20 次探测才通），API/codeload 一直通；用「探测通了再推」的后台脚本一次成功。

## 修复 v1.24.3：只认 tid/page 的采集站分类缺失（commit 169aa251，1.24.3+211，dev）
- 用户反馈：「有的网站只能获取到一个分类，其他分类获取不到」，例子 `http://movie.iqinu.com/api.php/v1.vod`。
- **实测结论（关键，别再猜）**：
  - 该站 `ac=list` **完全不返 class**（`?ac=list` / `ac=class` / 裸地址都只回最新 20 条 videolist），所以 `_classesFromJson` 空 → 只剩「最新」一个 tab，就是用户看到的现象。
  - 该站**无视 `t` 和 `pg`**（换 t/pg 返回完全一样，total 恒 137096），只认 **`tid` + `page`**；`tid=1..6` 分别 41966/25469/17260/8925/4475/39001（电影/连续剧/综艺/动漫/纪录/短剧），7 以上全 0。无子分类。
  - 返回里没 `pagecount`（只有 total/page/limit）→ `_mapPage` 默认 1 页 → 永远翻不动。已按 total/limit 自算。
  - 该站 `type` 字段是**对象**（`{type_id, type_name, type_pid, …}`），`_mapVideo` 取 `v['type_name']` 得空；若直接 `_s(v['type'])` 会把整串 Map 显示到卡片。已加 `_typeName()`。
  - 该站 detail 不返回 `vod_play_url`（41 个字段里没有），播放拿不到地址 —— 是站本身不给，非 App 问题。
  - `/api.php/provide/vod/` 标准入口返回 `closed`，无法绕到标准路径。
- 改动（`lib/services/http_service.dart`）：
  - `_listParams({tid, pg})` 统一拼 **`t`+`tid`、`pg`+`page` 双写**；标准 maccms 忽略未知参数（红牛实测带不带一致），非标准网关靠自己的那套生效。
  - `fetchClasses` 加第三级兜底 `_classesFromVideos`：从片单 `type` 反推分类（兼容 Map 对象 / 字符串 / 顶层 type_id+type_name）。
  - `_extendClasses` 并发探 `maxTid+1..+4` 补冷门分类（反推只覆盖最新一页，此站漏「短剧」tid=6，靠探测补上）；`_probeClass` 以「返回里有同 tid 的项」为存在判据，站忽略 tid 时不会凭空造分类。
  - `_mapPage` 缺 pagecount 时用 `ceil(total/limit)`；`_typeName()` 兼容 type 对象。
