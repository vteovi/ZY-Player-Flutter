## v1.29.1 冷启动首屏快照（dev，未推送）

- 用户反馈：上一版（1.29.0 封面索引）之后「还是慢，打开那一两秒钟还是空白，最好一打开就有内容、有海报」。
- **根因不是封面**，是首屏的**整条链路**都是异步的：
  1. `AppState.bootstrap()` 异步读 4 张表 → `FilmPage` 首帧 `_site == null`，只能画 EmptyHint / 空；
  2. `_loadClasses()` **只走网络**（分类列表从来没有缓存）→ 分类栏要等一次网络往返；
  3. CategoryTab 挂载后才 `ListCache` 读片单（又一层异步）。
  冷启动那一两秒就是这三段串起来。
- 解法：新增 `lib/services/boot_snapshot.dart`（`boot_screen.json`，存**结构**：site json + classes + 上次停留 tid；**不存片单**，片单仍从 `ListCache` 读，避免两份数据打架）。
  - `main()` 里 `await Future.wait([CoverCache.load(), BootSnapshot.load()])` —— 在 `runApp()` **之前**读进内存，首帧就有内容。
  - `BootSnapshot.load()` 里读 ListCache 的部分加了 `.timeout(500ms)`：这一步会触发 shared_preferences 首次初始化（整份偏好进内存），收藏/历史特别多时可能几百 ms，宁可只给结构也不能卡首帧。
- `film_page.dart`：
  - `initState` 先 `_applyBootSnapshot()`（站点/分类/`_initialIndex`/`_bootVideos` 一次就位），再建 `TabController(initialIndex: ...)`。
  - **`_usingSnapshot` 交接机制**：`_onAppStateChanged` 里若还在用快照，走新的 `_adoptRealSites()`（**不置 `_loading`**，所以不会闪骨架屏），只把站点对象换成库里那份 + 静默对分类；**不能**走 `reload()`（那会把刚显示的内容换成骨架屏）。
  - ⚠️ 时序坑：`create: (_) => AppState()..bootstrap()` 可能在 `FilmPage.initState` **之前**就跑完，那样 `addListener` 永远等不到 notify → initState 里必须顺手检查 `state.activeSites.isNotEmpty`，是则直接交接。
  - `_initTabs` 新增 `initialIndex` 参数（默认 0，保持换源回「最新」的旧行为）；**`length<=0` 时要先挡一层**，否则 `initialIndex.clamp(0, -1)` 抛 ArgumentError。
  - 新增 `_refreshClassesSilently()`：静默对齐分类栏，失败保持快照那份，变了才 `_initTabs(force, initialIndex: 保持当前 tid)`。
  - `_saveBootSnapshot()` 在 `_loadClasses` / `_onTabChanged` / `_refreshClassesSilently` / `_adoptRealSites` 后调用。
- `CategoryTab` 新增 `initialVideos`：有值就 `_videos.addAll` + `_loadedPages.add(1)` + `_seededFromSnapshot = true`，`_load()` 里见到该标记就**跳过读缓存**（快照本来就从 ListCache 读的，再读一遍纯浪费）直接 `_refresh()`。
  - `_bootVideos` 必须连 `_bootSiteKey` 一起校验：换源后同 tid 会把 A 站片单画到 B 站上。
- 顶栏资源数显示条件加 `_activeRecordCount > 0`：快照读不到元信息时不要显示「· 0 资源」。

## v1.32.0 搜索改为「边打边搜」（dev，未推送）
- 用户：「这个搜索，改成边搜边出结果呗，就是搜到什么就先展示出什么」。原本只能按回车/点「搜索」才开跑（结果虽分批出，但要先提交）。
- `search_page.dart` 改动：
  - `Timer? _debounce` + `static const Duration _debounceDelay = 450ms`，`_onTextChanged` → `_scheduleSearch()`。
  - **中文输入法关键坑**：`_controller.value.composing.isValid` 期间**不发搜索**（此时 text 是半截拼音/候选字），等 composing 结束落字监听会再触发一次。
  - `_doSearch(rawKeyword, {bool typeahead = false})`：typeahead 时**不 unfocus**（否则键盘一收没法继续打）、**不写搜索历史**（否则历史里全是「三」「三体」半截词）。
  - 结果替换策略改为**旧结果留到第一批新结果到达才 clear**（`var replaced = false` + 首批 setState 里 clear），两条路径都这样，避免每敲一个字闪一下空白。原先是进来就 `_results.clear()`。
  - `_resetToHistory` 拆成两个：`_resetToHistory`（× 按钮，clear 输入框）+ **新增 `_backToHistory`（只切回历史视图、不碰输入框）**。原因：`_controller.clear()` 会同步触发监听 → `_scheduleSearch` 见空文本 → 若又调 `_resetToHistory` 就是**无限递归**。删空输入框走 `_backToHistory`。
  - `_changeScope` 也改用 `typeahead: true`（不重复记历史、不闪空白）。
- 版本 1.31.1+225 → **1.32.0+226**（feat 升 MINOR）。更新记录已加。
- 本机无 Dart，靠 analyze.yml 兜编译。
- **⚠️ 用户澄清（同日晚些）：不要「边打边搜」**。原话：「不是边输入边搜索，搜索的时候，先搜到什么就展示出什么，不要搜一阵子然后统一展示出来」。上一条的 typeahead 全部撤掉（`_debounce` / `_lastKeyword` / `_scheduleSearch` / `_backToHistory` / `typeahead` 参数 / `dart:async` import 全删，`_resetToHistory` 恢复原样）。
  - **真正的病根在原来的分批逻辑**：`for` 循环里每批 12 个源走 `Future.wait`，**这批全部返回才 setState 一次** → 第一个源 300ms 回来了也得等这批最慢的（有的源超时 8s），所以看起来像「搜一阵子然后统一弹出」。
  - 改法：**游标 + 固定数量 worker 的并发池**（`_concurrency = 12`）：`var cursor = 0;` 每个 worker `while` 领一个 `cursor++`，单独 await 该源，**回来就 setState 追加**（`_done++`），领完退出。完成一个显示一个，总并发不变。
  - 语义差别记牢：`_done` 现在是「已完成的源数」，用来驱动进度条。
  - `_batchSize` 重命名为 `_concurrency`（含义从"每批大小"变成"总并发上限"）。
