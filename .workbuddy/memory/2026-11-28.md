# 2026-11-28 工作日志

## 冷启动优化：打开就有海报，不再只剩「刷新按钮」（v1.54.0）

- 参考项目：`D:\DouBao\CineHub\yingshu`（影枢 CineHub）。它的冷启动三件套：
  ① `PosterFileCache`（URL+宽 哈希成文件名，命中即一次磁盘读，不用查 sqflite 索引）；
  ② `PosterImageProvider`（自定义 ImageProvider，先读盘、再解码，解码结果进 Flutter 内存缓存）；
  ③ `main()` 里 `tuneImageMemoryCache()` 调大内存缓存 + `precachePosters()` 列表就绪后预取。
  首页数据侧则把 `CmsIndex`（分类 + 首屏片单）按源存进 prefs，`cachedIndex()` **同步**读，网络失败也继续显示缓存内容。
- 我们这边已有对应物（`CoverCache` 同步路径索引 + `ListCache` + `BootSnapshot`），但有两处漏：
  1. `BootSnapshot` 只存结构，片单要去 `ListCache` 读 → 触发 shared_preferences 首次初始化，
     带 500ms 超时，超时就没内容，`CategoryTab` 再走异步读缓存 + 网络，网络一失败就只剩重试按钮。
  2. 列表请求失败后**一次就判定失败**（`_loadFailed`），冷启动那一下的网络抖动直接变现成「刷新按钮」。
- 本轮改动：
  - `BootSnapshot` v2：片单头 30 条 + recordCount **内联**进 `boot_screen.json`，`load()` 不再碰 prefs
    （v1 老文件无 `videos` 字段仍回退 `ListCache`）。新增 `save(..., {videos, recordCount})`。
  - `FilmPageState._pageSnapshots`：每个分栏加载完（快照/缓存/网络任一来源）回写头部 30 条，
    退出前写进快照；`_saveBootSnapshot` 取当前分类那份，拿不到时沿用文件里同分类的旧数据，避免写空。
  - `didChangeAppLifecycleState`：paused / hidden / detached 时 `BootSnapshot.flush()` + `CoverCache.flush()`，
    不再等 600/800ms 防抖（杀进程太快会丢）。
  - `CategoryTabState._refresh()` 改为重试循环：`_doRefresh()` 返回 `bool`（是否需要重试），
    **4 秒内的快速失败**自动退避重试 2 次（1.2s / 2.5s），期间保持骨架屏；真超时或重试用尽才亮按钮。
  - `ImagePrefetch`：加全局串行队列（`_queue` + `_queued`），冷启动首批延迟 800ms 起跑，
    先让首屏接口请求占带宽；后续批次排前一批之后，避免「6 张 × N 栏」把接口挤超时。
