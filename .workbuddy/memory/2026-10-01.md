## http_service.dart 三项兼容性修复（2026-10-01）
背景：用户反馈「有的源加载不了」。修复**只改 `lib/services/http_service.dart` 一个文件**。

1. **请求方式**：新增 `_fetch()` = **GET 优先，仅在响应 4xx 时回退 POST**。
   原 `_post()`（所有接口统一 POST，对齐 uni-app uni-ajax）已删除。
   - 触发原因：`cj.lziapi.com`（量子资源）只放行 GET，POST 直接 403。
   - ⚠️ **关键设计**：DNS / 连接 / 超时这类**网络层失败不重试** ——
     换方法一样会失败，无脑重试会让一个死站白等 2×15s = 30s。
2. **解析方式**：不再由 `site.isJson`（即 `type` 字段）决定解析器，
   改为 `_parse()` 按**响应首字符自证**：`{`/`[`→JSON，`<`→XML，认不出则两种各试一次。
   结果装进新类 `_Payload{json, xmlDoc}`。
   - 触发原因：`淘片资源` 标注 `xml` 但实际返回 JSON。
   - 五个接口（fetchList / search / fetchDetail / fetchPage / fetchClasses）
     全部改走统一的 `_load()`；helper：`_videosFrom/_videosFromJson/_videosFromXml`、
     `_pageFromJson/_pageFromXml`、`_detailFromJson/_detailFromXml`、
     `_classesFromJson/_classesFromXml`。
   - `fetchClasses` 先试 `?ac=list` 再试裸 api，**网络失败立即返回**不试第二个地址。
3. **响应解码**：新增 `_decode()` —— 响应头没 `charset` 时按 **UTF-8** 解
   （`http` 包的 `res.body` 默认 latin1，中文站必乱码）。用
   `res.bodyBytes` + `utf8.decode(allowMalformed: true)`。
   ⚠️ GBK/GB2312 站仍不支持（`dart:convert` 无该 codec，`Encoding.getByName('gbk')` 返回 null），
   退回 UTF-8，与改前一样是乱码、不会更差。

⚠️ **踩坑**：`_Payload` 的字段一开始命名为 `xml`，**遮蔽了 `import 'package:xml/xml.dart' as xml`
的前缀**，analyzer 报 `PREFIX_SHADOWED_BY_LOCAL_DECLARATION`。改名 `xmlDoc` 解决。
→ **Dart 里不要用 import 前缀同名做字段名或局部变量名。**

- `Site.isJson` 改后已无引用，作为 public getter 保留（不会触发 unused 警告）。
- 静态检查：25 文件 `0 errors / 0 warnings / 0 lints`。

## 1.5.3：修复「导入不了 zyfun 导出的 JSON」+ URL 参数合并（2026-10-01）
用户反馈：「好像并不能导入 PC 版 zyfun 导出的 Json 文件」。

### 真实文件长什么样（一定要留档）
本机样本：`C:\Users\VTE\Documents\新建文件夹\zyfun_config_20260923_100544.json`
（12.3KB，UTF-8 无 BOM；同一份也在 `.trae-cn\attachments\...`）。

```json
{ "tbl_site": [ { "id":"c5dba7f4-...","key":"c5dba7f4-...","name":"百度资源",
  "api":"https://api.apibdzy.com/api.php/provide/vod/?ac=list",
  "playUrl":null,"search":1,"group":"默认","type":1,"ext":"","categories":"",
  "isActive":true } ] }
```

⚠️ 三个关键点，之前全都踩了：
1. **顶层键是 `tbl_site`**（数据库表名，新版 Tauri zyfun 的「数据管理 → 配置导出」），
   不是 `sites`。旧解析器只认 `sites`/`site` → 直接判「没有 sites 数据」。
   （另一种导出「源管理 → 导出」是**顶层裸数组**，也要认。）
   同批导出还可能有 `tbl_iptv` / `tbl_analyze` / `tbl_drive` / `tbl_star` 等表。
2. **`id` / `key` 是 UUID 字符串**（非 int）—— `Site.id` 只是装饰字段（记录身份用 `key`，
   见 `zy_database.dart` 全部按 `item['key']` 索引），取不到数字就留 0，无副作用。
3. **`api` 自带查询串**，35 条里 10 条形如 `.../vod/?ac=list`。
   原来 `'${site.api}?ac=videolist&pg=1'` 会拼成
   `.../vod/?ac=list?ac=videolist&pg=1` —— 服务端只取到第一个 `ac=list`，源就"加载不出来"。

### 改动
- `lib/services/source_import.dart`
  - 支持顶层**裸数组**（包一层成 `{'tbl_site': [...]}` 后统一处理）
  - `_extractSites` 键名**大小写不敏感**依次匹配 `tbl_site` → `sites` → `site`；
    值可以是数组，也可以是 `{"default":1,"data":[...]}` 包装（`_listFromValue`）
  - 兜底：扫顶层数组，**要求元素带 `api`** —— IPTV/解析源用 `url`，这样不会误选
    （已实测：只有 `tbl_iptv` 的导出会被正确拒绝并提示顶层字段名）
  - 失败提示改为回显顶层字段名，便于用户判断是哪种导出格式
  - `_decode` 换成 `_embeddedJson`（先按 `{}` 再按 `[]` 截取嵌入 JSON）
- `lib/services/http_service.dart`
  - 新增 `static String _apiUrl(Site, Map<String,String>)`：用 `Uri.replace(queryParameters:)`
    **合并**站点自带参数与本次调用参数（本次覆盖同名项），既去重复又正确编码中文 `wd`。
    5 处调用全换：`fetchClasses`(ac=list)/`fetchList`/`fetchPage`/`search`(wd)/`fetchDetail`。
    ⚠️ **不要退回字符串拼接**。
  - `importSites(url)`（地址导入）改为也走 `SourceImport.parse`，与本地文件导入同一套解析。
- `lib/pages/me_page.dart`：读文件改 `readAsBytes` + `utf8.decode(allowMalformed: true)`，
