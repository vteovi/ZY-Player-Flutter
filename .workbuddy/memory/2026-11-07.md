## 修复 Windows 端设备同步卡死（commit ce3fd0fb，1.20.2+202）
- **根因（实锤，读了包源码）**：`shared_preferences_windows-2.4.1/lib/shared_preferences_windows.dart:374-399`，每次 `setValue` → `_cachedPreferences[key]=value` → `_writePreferences` → `json.encode(整个 prefs map)` + `localDataFile.writeAsStringSync(...)`。**全量序列化 + 同步整文件重写**，全在 UI isolate。`ZyDatabase.importRaw` 又是逐条 `put`，几百条历史 = N 次全量写 + N 次全量序列化，界面直接僵住。Android 侧重写在原生线程，所以只有 Windows 端特别明显。
- 包源码路径：`D:\WorkBuddy\water_delivery\.local\Pub\Cache\hosted\pub.flutter-io.cn\shared_preferences_windows-2.4.1`（本机 pub cache 不在默认位置，`package_config.json` 里的 rootUri 指向不存在的路径，别被误导）。
- 修法：`importRaw` 改成「一次读 oldKeys → 逐条比对 `store.getString`（内存缓存，无 IO）→ 只 setString 差异 → key 列表合并重排后只写一次」。内容完全一致时直接 `return 0`，零写入。`_reorderKeysAfterImport` 合并进来后删除。返回值语义从「处理条数」变为「变化条数」，`sync_page` 相应改成显示「数据已是最新」。
- 新增 `onProgress(done,total)` 贯穿 `ZyDatabase.importRaw` → `AppState.importDbs` → `sync_page`，写入阶段显示「正在写入 收藏 40/120 条」。
- `SyncClient`：`connectTimeout` 10s；接收改 `response.timeout(idleTimeout=20s)`（Stream.timeout 是块间隔超时，有数据在来就不算断），`BytesBuilder(copy:false)` 攒包，`onProgress` 回调已收字节；`isCancelled` 抛 `SyncCancelled`。删除旧的 `defaultTimeout`/`timeout` 参数。
- `SyncServer.start` 参数从「payload」改为「load 回调」，每次请求实时 `exportDbs` —— 修掉「开启共享那一刻的快照」bug；`server.idleTimeout=15s`；响应带 `contentLength` 让对端能算进度。
- `sync_page`：`_syncPhase` 分阶段文案 + `_cancelEnabled`（只在接收阶段可取消，写库中途不许停）+ 进度节流 80ms；共享页加「同步期间保持屏幕常亮」。
- 验证：本地无 Dart，靠 CI `Analyze`（run 42343967990）`success`。
